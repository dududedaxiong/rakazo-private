# Agent Note: 余额不足的 400（中文措辞）也切换模型

Status: implemented

## Problem

2026-11-21 一轮对话在第一个模型上直接失败，没有发生任何切换：提供方返回 400 `content_filter`，文案是“内容审核未能完成（余额不足，请充值后再试）”。日志里 30 分钟内零切换记录，run 以 failed 终结。

根因在分类器，不在链子。执行器的切换链来自成员的主模型角色（主池 + 备用池），那轮的链子非空；切换门只开给 `isRetryableProviderUnavailable` 与 `isModelCredentialRejected` 认的错。`isRetryableProviderUnavailable` 里已有“账户耗尽就切换”的规则（`isAccountExhaustion`：400 / 402 / 403 + 明确的耗尽措辞），但它的耗尽信号 `EXHAUSTION_SIGNAL` 只有英文措辞（insufficient balance / out of credits / quota exceeded 之类）。中文“余额不足，请充值”一句英文都不沾，`isAccountExhaustion` 返回 false，随后 `statuses.has(400)` 直接判不可切换。余额耗尽本该是切换的错，只因措辞是中文而被当成坏请求。

这篇翻转了[模型切换缺口补齐](./../feature/2026-11-20-model-fallback-gaps.md) §8 的一句话：“400 / 403 / 模型不存在等不可切换错误、分类器不动”。那句话本来就不精确：英文的 400 余额不足当时已经可切换（`isAccountExhaustion` 与单测在先）；真正缺的是中文措辞的识别。翻转只针对“明确说余额/额度耗尽的 400”，不针对 400 本身。

## Decision

`EXHAUSTION_SIGNAL`（`packages/adapter-kit/src/model-errors.ts`）补中文耗尽措辞，与英文同一规则：400 / 402 / 403 + 明确说耗尽才算，401 永远不算。

- 余额：`余额不足`、`余额不够`、`余额已用完`、`余额耗尽`、`余额用完`
- 额度：`额度不足`、`额度不够`、`额度已用完`、`额度耗尽`、`额度用完`
- 配额：`配额不足`、`配额已用完`、`配额耗尽`、`配额用完`
- 用量与积分：`用量不足`、`用量已用完`、`积分不足`、`积分已用完`、`积分耗尽`
- 欠费与充值：`欠费`、`请充值`

中文的 `NOT_EXHAUSTION` 不补：没有耗尽措辞的中文鉴权/参数错误本来就匹配不上 `EXHAUSTION_SIGNAL`，守卫只在“既说耗尽、又说别的终结原因”的消息上才起作用，那种消息罕见，且切过去也是良性的（备选报同样的错，时间线会记下来）。

其余行为不动：

- 耗尽仍不是瞬时错误——`isTransientModelError` 对它返回 false，同模型不重试，直接换备选（分类器自己的注释早已这样定：耗尽的账户在重试预算内不会恢复）。
- 只有 `isRetryableProviderUnavailable` 的调用方受益，即聊天与电脑操作走的 `fallbackAwareModelStream`（`packages/adapters/src/pi-runtime-fallback.ts`）；媒体链与翻译链不用这个分类器，不受影响。
- 真正的内容拦截（只有 `content_filter`、不提余额）仍不切换：它匹配不上任何耗尽措辞。

## Alternatives considered

- **所有 400 都切换**——最强的理由：最简单，任何提供方侧的 400 都能切走。否掉：坏参数、模型不存在这类错对池子里每个模型都一样报，切换只会白烧整个池子；2026-11-20 那篇否掉它的理由对非耗尽 400 仍然成立。
- **只认 `content_filter` 类型**——最强的理由：改动最小，只放行这一种已观测到的错。否掉：耗尽是账户的属性，不是过滤器的属性；同一句“余额不足”换个类型（如 `insufficient_balance_error`）也该切，按类型匹配会漏掉它。
- **中文 `NOT_EXHAUSTION` 也补齐**——最强的理由：与英文侧对称，防止中文鉴权/参数错误被误判成耗尽。否掉：那些错误本来就匹配不上耗尽信号，守卫没有可守的东西；只在“既耗尽又终结”的混合消息上才有差别，那种消息罕见且切过去无害。
- **余额不足当瞬时错误，同模型重试**——最强的理由：重试比切换便宜，不用换模型。否掉：耗尽的账户在重试预算内不会恢复，重试只会再撞同一个 400；分类器的既有设计就是耗尽走切换、不走重试。

## Consequences

- 聊天与电脑操作的切换门现在认中文余额/额度耗尽：400 / 402 / 403 + 上述措辞 → 切备选；同模型不重试。单测覆盖已观测到的原文（400 `content_filter`“内容审核未能完成（余额不足，请充值后再试）”）、纯文本形式、402 额度已用完、403 欠费；反例覆盖无余额措辞的内容拦截、余额查询失败、余额字段校验、401 包着余额不足。
- 已知局限：切换换的是模型，不是账户。链子里的模型若共用同一个耗尽的账户（例如同一家中转的多个模型），切过去会报同样的错、逐个耗尽整条链，时间线会把每次尝试记下来。配一个不同提供方的模型进链子才能真正绕开，这是模型配置层面的事，不归本批。
- [模型切换缺口补齐](./../feature/2026-11-20-model-fallback-gaps.md) §8 的“400 不可切换”已按本篇收窄，两篇互链。
