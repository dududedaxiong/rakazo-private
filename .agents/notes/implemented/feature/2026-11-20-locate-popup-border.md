# Agent Note: 定位先弹小窗确认、被定位行加有色边框（附手机端三处同路修复）

Status: implemented

## Problem

用户 2026-11-20 10:50 亲口要求改定位流程，10:52 又发录屏补了三处手机端问题，都在定位/设置这一路上：

- 点切换记录里的模型名直接跳走：同名模型在不同连接上各有一行，跳过去之前看不到到底要定位哪一个；入口处的名字被截断时更容易点错。
- 被定位行只有底色（`bg-accent`）+「定位到这里」标记，没有描边，在列表里不够醒目。
- （录屏）点切换记录里的模型名跳到设置面板后，「切换记录」弹窗还盖在设置面板上面。
- （录屏）手机上打开设置、点模型名定位后键盘弹起占半屏，滑设置列表时键盘还一直开着。
- （录屏）手机上图片编辑模型等下拉框只显示「cogview-3-fla…」，模型名被截断。
- （2026-11-20 11:00 用户发截图圈出）备用池里普通行（cogview-3-flash）的名字也被截成「cogview-3-flash (…」：用户原话「能不能搞成上面是模型名*提供方，下面就是测试，排序，删除」，又补「类似横幅卡片」——每行是一个卡片，上面一条是模型名+提供方的大横幅（整行通栏、醒目、完整显示、不截断），下面是测试、上移、下移、删除；不是两行纯文本，是带卡片感的横幅。
- （2026-11-20 11:04 用户亲口）点横幅卡片看模型详情：点卡片的横幅/名字区域（不是操作按钮），展开显示这个模型的具体信息（提供方、模型 id、支持的类型、有的数据）；只展示真实有的数据，没有的不要编造、不要猜；展开/收起可切换；操作按钮不要触发展开。
- （2026-11-20 11:04 用户亲口）测试前面加「替换模型」：操作行顺序改成替换、测试、上移、下移、删除；点替换打开与添加模型同一个选模型器，选一个模型就地换掉当前这一条，位置/顺序不变；只换这一条，不动池子里其他模型。

相关笔记：[模型切换缺口补齐](./2026-11-20-model-fallback-gaps.md) §4（模型名可点定位）、§14（被定位行完整名字；其中「没被定位的行保持单行紧凑」已被本次用户要求作废，见 §3）。

## Decision

### 1. 定位先弹小窗，点名字再跳转

新增 `ModelLocatePopup`（`apps/web/src/pages/shell/model-switch-history-dialog.tsx`，复用已有的 Dialog 原语，默认小尺寸）：

- 点切换记录对话框里的模型名（或无时间线时「当前模型」栏的 `ModelSwitchMarkButton`）时，先不跳转：关闭切换记录对话框，弹出小窗。小窗标题「定位到」，名字本身就是一个按钮，显示完整 label（模型名 + 提供方，例如 `cogview-3-flash（智谱）`），可换行、不截断；下面一行小字提示「点击前往」。
- 点小窗里的名字：小窗关闭，触发定位（跳到设置页里该模型所在的列表、滚动到那一行）。名字是唯一的确认目标，不另加确认按钮、不多一步确认框。
- 点小窗外的区域、按 Esc、点右上角 X：只关小窗，不跳转，回到对话。

### 2. 跳转时两个弹窗都关掉，不盖设置面板

现行流程里，切换记录的关闭只靠对话框自己在跳转前调一次 `onOpenChange(false)`；跳转点（`ModelSwitchHistoryEntry` 传出的 `onLocateModel`）没有任何保证。录屏里弹窗盖住设置面板，说明那一次关闭在手机上没生效——至于是关闭调用被面板切换打断、还是对话框在导航中重挂后状态复位，单凭录屏无法定论，所以修法不再依赖那一次调用：

- `ModelSwitchHistoryEntry` 把传给对话框的 `onLocateModel` 包一层：先 `setOpen(false)` 再转发，持有 `open` 状态的一方在跳转点亲自关掉对话框。
- 小窗确认路径同样先关小窗、再关切换记录对话框，最后才触发定位。
- Entry 级单测锁定：打开对话框 → 点模型名 → 点小窗名字 → 切换记录对话框已从文档里消失，且 `onLocateModel` 只调了一次。

### 3. 模型列表行统一两行横幅卡片

`MediaModelFallbackList` 的每一行（主池/备用池，全部家族：生图/视频/编辑/翻译）都是一个卡片，不再分被定位与没被定位两种排布——上一批「没被定位的行保持单行紧凑」已被用户 11:00 的要求作废：

- 卡片：`rounded-lg border-2 bg-muted/50 px-3 py-2`，列表里行间距 `space-y-2`。
- 上面一行是横幅头：完整 label（`withConnectionName` 的「模型名（提供方）」，例如 `cogview-3-flash（智谱）`），`break-words` 可换行、不截断，`font-medium text-foreground`，整行通栏。
- 下面一行是按钮：测试（有探针的家族）、上移、下移、删除；被定位时「定位到这里」标记也在这一行打头。
- 主模型选择器那行（`MediaRoleSection`/`TranslationGroup` 的主模型下拉）不是池子行，不动两行排布，只按 §6 修截断。

### 4. 被定位的卡片加 2px 有色边框

§3 的卡片上，被定位时边框换成 `border-primary`、底色换成 `bg-accent`；没被定位的卡片是透明边框（`border-transparent`），定位前后布局不移位。聊天节卡片本来就有 `ring-1 ring-primary/40`，改成 `ring-2 ring-primary`，与卡片的 2px 描边同级；翻译与影图主模型行（不是池子行）被定位时同样加 `border-2 border-primary`（没被定位时 `border-transparent`）。定位本身的滚动与高亮逻辑不动，只加边框；「定位到这里」标记保留。

边框颜色选 `primary`（墨色）而不是用户举例的 accent：accent token 是半透明灰填充（浅色 `#78788029`、深色 `#78788052`），2px 细线在底色上几乎看不见，达不到「一眼认出来」；primary 是 `LocatedTag` 的描边色与聊天卡片 ring 已在用的颜色，被定位行的描边与现有定位标记同色。link 蓝也考虑过，与已有的定位标记不同色，所以不用。

### 7. 卡片横幅可点开看模型详情

横幅（名字那一行）本身是一个按钮（`aria-expanded`，右端一个下箭头，展开时转 180°），点它展开/收起详情；操作按钮在横幅下面的另一行，不触发展开。一次只展开一张卡（再点另一张就换过去，点同一张收起）。

详情只展示代码里实际有的数据（`MediaModelFallback` 本身只有 `key` + `label`，其余都从 key 与连接选项里取，不编造、不猜）：

- **提供方**：`choices`（`ChatModelChoice[]`，`MediaRoleSection`/`TranslationGroup` 本来就有的全量连接选项）里按 key 查到的 `providerLabel`；查不到时退到 key 里解析出的提供方 id（`parseModelOptionKey`），再没有就不显示这一行。
- **模型 ID**：`choice.modelId ?? parseModelOptionKey(key).modelId`，即 key 里 `provider::modelId` 的后半段（例如 `cogview-3-flash`），不是横幅上那个带提供方的 label。
- **图片输入**：只在目录知道时显示（`choice.images !== undefined`）：`true` →「支持」，`false` →「不支持」。自由填的模型 id 目录不知道，就不显示这一行，不猜。
- **位置**：池子 + 序号（主池第 N 位 / 备用池第 N 位），列表本身就有的数据。

**没有用量统计**：设置页这个作用域里没有按模型分的用量数据（用量页是另一页、自己拉数；`choices` 与 `MediaModelFallback` 里都没有）。用户说「以代码里实际有的为准」，所以详情里不放用量统计；要放就得新拉一份用量数据，那是另一个改动，不在这批。

### 8. 操作行第一位加「替换模型」

顺序改成：替换、测试、上移、下移、删除（「定位到这里」标记仍在最前，它不是操作）。替换用与「添加模型」同一个选模型器：`NativeSelect`（`size="sm"`），选项就是 `addChoices`（已排除池子里在用的 key，不会换出重复），占位文案就是「替换模型」，`value=""` 受控、选完即回到占位——与下面那个「添加模型」下拉完全同一套写法；手机上同样走原生选择器，不弹键盘、不截断。

替换只换这一条：`onReplace(oldKey, newKey)`，`bot-panel.tsx` 里按 key 在池数组里原位 swap（`replaceMediaPoolFallback` / `replaceTranslationPoolFallback`，与已有的 add/move/remove 同一套写法：先 `parseModelOptionKey(newKey)`，解析不出直接返回；新模型已在另一池或本池别处时拒绝，沿用 add 的去重规则）。位置/顺序不变，不动池子里其他模型。主模型行不用替换——它本身就是选择器，直接选就是换。

### 9. 手机键盘：选择器自动打开时不聚焦搜索框

根因：定位 kind 为聊天（或模型数 >10 的家族）时，`ChatModelPicker` 的 `autoOpen` 把选择器弹层自动打开；Base UI Popover 没传 `initialFocus` 时默认把焦点送进弹层里第一个可聚焦元素——cmdk 搜索输入框，于是手机键盘弹起，弹层开着、焦点一直在输入框上，滑列表键盘也不下去。cmdk 的聚焦只发生在按键时，挂载时把焦点送进去的是 Popover 的默认 initial focus；`bot-panel.tsx` 的 `.focus()` 只对准选择器触发器（按钮或原生 select），从不对文本输入框聚焦，不是键盘来源，保留不动。

修法：`ChatModelPicker` 用已有的 `useMedia("(pointer: coarse)")` 判触屏，粗指针设备上给 `PopoverContent` 传 `initialFocus={false}`——弹层照常打开在被定位的行上，焦点留在触发器上，键盘不弹；用户自己点搜索框时才聚焦、才弹键盘。细指针（桌面）保持默认行为不变。附带：`useMedia` 本来假设 `matchMedia` 一定存在，没有它的环境（jsdom、服务端渲染）直接炸掉；本批把它改成缺失时返回 `false`，否则每个渲染选择器的测试都要补 stub。

### 10. 下拉框模型名截断：触发器换行 + 主模型行换行

根因：`MediaRoleSection` 的主模型行把标签、选择器、「测试」按钮（和定位标记）挤在一行，选择器分到的宽度不够；搜索模式下触发器 `truncate` 截断，模型数 ≤10 时的原生 select 根本不能换行，只能截断——手机上「cogview-3-flash」只剩「cogview-3-fla…」。

修法分两处，都在 `ChatModelPicker` 与 `bot-settings-sections.tsx`，一处改好、各家族通用：

- 选择器触发器：名字去掉 `truncate`，改成 `break-words` 换行，触发器 `h-8` 改成 `min-h-8` + 纵向留白，名字长了长高一行显示，不截断。
- `MediaRoleSection` 与 `TranslationGroup` 的主模型行：外层加 `flex-wrap`，选择器容器给一个最小宽度（`min-w-64` / `min-w-56`）；窄屏上选择器整块掉到下一行占满宽，原生 select 拿到整行宽度，名字显示全。宽屏上一行不变。

## Alternatives considered

- **详情里也放用量统计**：最强的理由是用户原话里提到了用量统计。但设置页这个作用域里没有按模型分的用量数据，硬放就得新拉一份数据（新接口或新 hook），那是另一个改动；用户原话也加了「以代码里实际有的为准」，所以本批不放，只在笔记里记下这个缺口。
- **替换做成弹窗选模型器而不是 NativeSelect**：最强的理由是弹窗里能搜、能看全名。但「添加模型」本身就是 NativeSelect（原生选择器），用户明确要求「同一个选模型器」；手机上原生选择器是系统弹窗，本来就能看全名、不用键盘；所以用同一套 NativeSelect，不另起弹窗。
- **横幅卡片只给被定位行、其他行保持单行紧凑**：最强的理由是列表更短、信息密度高。但用户 11:00 亲口作废了这条：普通备用池行的名字也被截断（截图里 `cogview-3-flash (…`），只修被定位行治标不治本；统一两行后每一行都完整显示名字，扫列表不用逐行点开。
- **横幅卡片的名字行再加一条底色条**：最强的理由是横幅头更像横幅。但卡片本身已有底色，名字行再加一条底色是两层嵌套，视觉上重；名字行用 `font-medium text-foreground` 在卡片底色上已经够醒目，所以不加。
- **小窗改用原生菜单或自定义浮层**：最强的理由是不用再套一层 Dialog，轻。但名字必须完整显示、可点、点外面关闭不跳转，这些 Dialog 原语都现成（外面点击关闭、Esc、X），手写浮层要自己补焦点与关闭逻辑；所以复用 Dialog。
- **小窗打开时切换记录对话框留在后面（嵌套弹窗）**：最强的理由是关掉小窗还能回到切换记录再挑一个。但两层弹窗要处理两套焦点陷阱与遮罩，代码变复杂；现行定位本来就是点名字即关对话框，所以小窗打开时关掉它，行为与原来一致。
- **边框用 accent（用户举例的颜色）**：最强的理由是用户亲口举例，且与被定位行的底色同系。但 accent 是半透明灰填充，2px 细线在底色上几乎看不见，达不到用户要的「一眼认出来」；所以用 primary。
- **边框用 link 蓝**：最强的理由是真正「有色」，且与可点的模型名同色，点哪行、框哪行。但与已有的定位标记（LocatedTag 的 primary 描边、聊天卡片的 primary ring）不同色，一页里两种定位色；所以统一用 primary。
- **键盘：手机上干脆不自动打开选择器弹层**：最强的理由是连弹层都不开，键盘自然不会弹。但弹层打开在被定位行上本身有用（用户一眼看到那行），问题只在焦点；`initialFocus={false}` 只关焦点、不关弹层，更贴着问题改。
- **键盘：打开后 `blur()` 一下输入框**：最强的理由是改动只有一行。但要跟 Popover 的焦点管理抢时序，时序一变就复发；`initialFocus={false}` 是 Popover 官方提供的开关，不抢时序。
- **下拉框：把原生 select 换成自定义列表**：最强的理由是自定义列表能换行、能完全控制显示。但短列表用原生 select 是全站既定做法，问题在行宽不在组件；换组件是重写，所以只改布局（触发器换行 + 行换行）。

## Consequences

- 定位多一步：每次点模型名都先弹小窗，点名字才跳转；点错名字时，关小窗即可，不会跳错地方。
- 跳转时两个弹窗都关掉的保证落在持有 `open` 状态的 Entry 与小窗确认路径上，有 Entry 级单测锁定；对话框自己跳转前那一次关闭仍在，双保险。
- 模型列表行统一是两行横幅卡片（名字横幅头 + 按钮行），被定位的卡片再加 2px primary 描边 + 底色；没被定位的卡片是透明边框，定位前后布局不移位。列表比原来高（每行两行），换来的是每一行的名字都完整可见。
- 横幅可点开看详情（提供方、模型 ID、图片输入、位置），只显示真实有的数据；详情里没有用量统计（设置页作用域里没有这个数据）。
- 操作行顺序是替换、测试、上移、下移、删除；替换就地换一条、位置不变，选不到已在池子里的模型。
- 粗指针设备上选择器弹层打开时不再聚焦搜索框（桌面不变）；键盘只在用户自己点搜索框时弹起。
- 选择器触发器名字换行显示；影图/翻译主模型行在窄屏上换行占满宽，原生 select 显示完整模型名。
- 新增文案两条（「定位到」「点击前往」），走 Lingui extract + zh-CN/zh-TW 翻译 + compile。
- 未做：视频失败行仍无切换时间线入口（见[失败原因进对话](./2026-11-20-failed-run-reason-display.md)已知缺口）；`splitBotModelPools` 主池空、备用池有模型时丢备用池的显示问题仍在（见[模型切换缺口补齐](./2026-11-20-model-fallback-gaps.md) §13）。
