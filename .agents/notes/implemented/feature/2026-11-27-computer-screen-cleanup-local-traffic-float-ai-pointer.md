# Agent Note: 电脑画面去杂、本地流量悬浮开关与 AI 点击指示

Status: implemented

## Problem

用户在手机上看机器人操作电脑时，电脑画面上有三类干扰：

- **操作面板太多**：小窗口（「电脑画面」悬浮窗）里，屏幕页面自己画了一排控制按钮（`+`/`-` 缩放、`^`/`v` 滚动、Esc/Tab/Ctrl、四个方向键、粘贴/键盘/手柄），盖住了画面。接管后也一样，`+`/`-` 与四个方向键仍然挡着屏幕。
- **看不见 AI 点了哪里**：AI 在电脑上操作时，用户看不到它点的具体位置，点错了也无法纠正。这是核心需求，不是点缀：指示必须醒目、位置准确、停留足够久（几秒，或到下一次操作），小窗口与全屏都要有。
- **本地流量没有开关**：走手机本地网络（而不是服务端数据中心出口）的能力还没有入口；用户要一个能随时开关的控制。

三件事的约束不同：去杂与开关是纯 App 改动；点击指示的坐标在 App 里根本拿不到——线程事件只带工具名，屏幕状态里没有指针，noVNC 的光标画布只跟用户的本地鼠标——所以它必须有一条服务端到 App 的坐标通道，否则只能造一个假的指示。

## Decision

### 1. 操作面板：App 往屏幕页里注入一段 `<style>` 藏起来，不改原生代码、不改沙箱镜像

按钮是屏幕页（noVNC 页面，来自电脑沙箱镜像）自己画的，不是 App 的原生视图，所以 App 在 WebView 里注入一段样式隐藏它们（`apps/mobile/lib/computer-screen-chrome.ts`，`computerScreenChromeScript(mode)`）。样式按 id 与 `data-key` 定位控件，用 `!important`，注入一次、重复注入不产生第二个 `<style>`。选这条路是因为线上镜像跑的页面版本可能比仓库里的 `embed.html` 新（实测上游已多出 `#mobile-view-controls` 一组缩放/滚动按钮），按名字隐藏对两个版本都有效，不用重建镜像、不用等部署。

- 小窗口（悬浮窗）与全屏未接管时是 `float`：四个面板全藏（缩放/滚动组、按键栏、粘贴/键盘/手柄行、noVNC 自带控制条）。
- 全屏接管后是 `takeover`：只藏缩放/滚动组与四个方向键，Esc/Tab/Ctrl 与粘贴/键盘/手柄行留给正在操作的用户。全屏的模式跟随是否接管（`hasControl ? "takeover" : "float"`），接管时 WebView 本来就会重挂，模式跟着换。
- 注入点：悬浮窗的 WebView 与全屏页的 `ScreenWebView`（后者把去杂脚本与原有的键盘就绪探针拼成一段注入）。

### 2. 本地流量：一个可拖动的悬浮开关，代替之前定的两个固定位置

`apps/mobile/components/computer-local-traffic-float.tsx`：一个 44pt 的圆形按钮，浮在屏幕内容之上（小窗口与全屏各挂一个，共用同一份状态）。点按切换开/关，拖动挪位置，位置按屏幕占比存下来，下次还在原处。开是实心主色 wifi 图标，关是描边 wifi-slash 图标，关时略透明，一眼能分清。按钮容器不拦截屏幕触摸（`pointerEvents="box-none"`），只有按钮本身吃点按与拖动。

开关只记偏好，不认领路由：实际把机器人浏览器流量走手机的后端通道（服务端到客户端的任务通道、WebView 执行器、在线状态）还不存在，所以开时只显示一句「已保存，配套更新到达后生效」，不谎称已生效。偏好与位置存在 SecureStore（`apps/mobile/lib/computer-local-traffic.ts`，沿用悬浮窗设置的存储模式），全 App 一份，不按 bot 区分（这是手机网络的事，不是某个 bot 的事）。新文案走 `t()`，翻译 catalog 不动——新串在翻译流程补上之前显示英文。

固定位置的两个方案（悬浮窗标题栏全屏图标左侧、「释放控制」左侧）按用户最后的决定撤掉，只留这一个悬浮开关，不给同一个设置造两个入口。

### 3. AI 点击指示：服务端把观测到的指针位置发出来，App 在屏幕上画一个醒目的标记

分两半，缺一半都不工作：

- **服务端（`packages/adapters/src/tool-completion-audit.ts`，17 行）**：工具完成审计的 payload 本来就从观测详情里抄 `frameId`、`capturedAt`、`width`、`height`，现在再抄一个 `cursor: {x, y}`。这个值是观测时读到的桌面实时指针位置（与帧同坐标系），不是调用方请求的点击坐标，所以标记落的是指针实际在的地方。只抄位置，不抄观测的其他内容；坐标不是秘密，不用脱敏；畸形的指针直接丢掉，不往下传。
- **App**：线程直播（`apps/mobile/lib/thread-live.ts`）收到 `agent.tool.completed` 事件时，用 `extractComputerPointer`（`apps/mobile/lib/computer-pointer.ts`）提指针——只认 `computer_act`（它的指针才是桌面指针），要求指针与帧尺寸都是有限数、bot 有 id；只接受新到的事件，断线续订不会把旧指针复活。指针进一个内存 store（不落盘，重启即失），`ComputerPointerMarker`（`apps/mobile/components/computer-pointer-marker.tsx`）在三个屏幕面（悬浮窗、预览、全屏）上画标记。

标记的样子（按“醒目、准确、停留够久”做的）：圆点正好落在点击坐标上（12pt，墨色加白边）；64pt 圆环 + 白色光晕围住它，深色浅色桌面都看得见；36pt 光标箭头（iOS 用 `cursorarrow`，Android 的 Ionicons 没有光标字形，用指向相同的 `arrow-up-left-box`），箭尖朝向圆点。标记完全显示 4.5 秒，再用 0.6 秒淡出；下一次 AI 操作立刻换成新位置并重新计时。标记不拦截触摸，纯视觉。坐标映射按帧与容器的宽高比修正黑边（帧在容器里按比例居中显示），所以黑边存在时标记也不会偏；只认本 bot 的指针，换 bot 不会串。

## Alternatives considered

- **把 noVNC 的光标画布放大**——光标画布只跟用户的本地鼠标，AI 操作时它停在用户上次触摸的地方。放大等于在错误的位置画一个大箭头，误导用户去纠一个不存在的错。否。
- **从工具结果文本里解析点击坐标**——坐标确实在返回给模型的文本里，但屏幕组件不消费聊天消息，解析自由文本也脆；观测详情里本来就有结构化指针，走事件通道更直接。否。
- **用 `agent.tool.called` 的参数当坐标**——参数里有请求的点击点，但没有帧尺寸，App 没法归一化；而且那是“要求点哪里”，不是“指针实际在哪里”。观测到的指针更准，还自带帧尺寸。否。
- **改沙箱镜像的 `embed.html` 删按钮**——要重建镜像、重新部署才生效，且线上镜像版本与仓库不同步的问题还在。注入样式不碰镜像，对任何页面版本都有效。否。
- **固定位置的开关（标题栏 /「释放控制」旁）**——用户最后改成悬浮按钮；两个固定入口管同一个设置会重复状态，悬浮按钮在哪个面都能摸到。否，按最后的决定只留悬浮开关。
- **用原生 Switch 做开关**——仓库约定优先用原生控件，但 Switch 不能浮在 WebView 上拖动；可拖动的悬浮控制没有原生等价物。否。
- **全量同步上游**——与本次三件事无关，上游领先太多，早已决定只 cherry-pick。否。

## Consequences

- **收益**：小窗口与全屏不再被页面自带的控制面板盖住；接管后只剩真正需要的键；本地流量有了随时能摸到的开关；AI 每次操作后，用户能在大小两个画面上看到一个醒目的标记，落在真实点击处，停留约 5 秒，点错了能立刻发现。
- **代价与已知上限**：
  - 标记要等服务端部署后才有坐标可画：部署前 App 收不到指针，标记不出现（不画假的）。服务端改动与 App 改动在同一分支、未推送、未部署，走正常的发布流程。
  - 开关目前只是偏好记录，路由后端未到；提示文案已说明这一点。
  - 新文案（开关标签、保存提示）走 `t()` 但翻译 catalog 未动，翻译补上之前显示英文。
  - 标记的映射假设帧在容器里居中显示（noVNC 的默认行为）；箭尖位置是字形近似，圆点才是精确点。
  - App 打包已暂停，这些改动要等用户下次打包新 App 才会到手机上，服务端部署带不上去。
  - 去杂只按页面控件的 id 与 `data-key` 隐藏；如果上游页面改名，注入会失效，需要跟着改选择器（测试会先发现）。
