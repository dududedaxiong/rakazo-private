# Agent Note: 用量页一键清空悬浮、柱状图标签不再压字

Status: implemented

## Problem

用量明细页（`apps/mobile/app/(settings)/usage.tsx`）两处用户反馈（2026-11-19 手机实测）：

1. **一键清空在页面最底部**：`resetUsage`（`rpc("usage/reset")` + 确认框）已实现，见 [App 用量重置](./2026-11-17-app-usage-reset.md)，但按钮在 `resetWrap` 里、排在通话明细与规则说明之后，用户要翻到底才找得到。重置是高频的收尾操作（看完用量就想清），放底部等于藏起来。
2. **近 7 天柱状图数值标签还会压字**：54f6efa 已修过一次（柱子高度改按轨道 `barTrack` 的百分比，见同一篇用量重置笔记 §「App 用量页柱状图数值标签压标题」），当时验算「最高柱 100% 即 55px，数值标签稳稳落在卡片内」。用户在新包上仍看到压字，说明只靠轨道隔离不够。剩下的碰撞路径有三条：最高柱顶到标签之间只有列 `gap: 6` 的间隙，视觉上几乎贴住；标签行没有固定高度，`compactTokenCount` 在大值下会出 5–6 字的串（`1200万`、`10000万`），窄屏下换行成两行、把轨道挤短，标签与柱顶的距离跟着变；系统字体放大时标签行高跟着涨，同一问题被放大。

## Decision

1. **重置按钮是悬浮按钮、始终可见**：不放在页面顶部，浮在内容上方，滚动时也一直在。位置按 App 现有悬浮按钮的惯例（对话页 `JumpToLatestButton` 同款）：右下角，`position: "absolute"`，`end: 16`，`bottom: 安全区底 + 12`；圆角胶囊（高 44），与 `ScrollToBottomButtonFallback` 同款阴影与海拔（shadowOffset 0/2、opacity 0.12、radius 4、elevation 2）、卡片底色、细边框；文案就是 `t("Reset usage")`（破坏性红字），不加图标、不加解释文案。点开仍是同一确认框、同一 `rpc("usage/reset")`、同一刷新行为（`load()`）；重置中按钮禁用并显示转圈（与旧 `NativeActionButton` 的 busy 同款反馈）。底部 `resetWrap` 已删，全页只留一处。滚动到底时不挡住关键内容：滚动内容的 `paddingBottom` 从 32 加到 80（按钮 44 高 + 上下各 12 间隙），最后一行能滚到按钮上方。
2. **柱状图从结构上修到标签碰不到柱子和标题**，三处一起改，不只调一个数：
   - 标签行固定高度：一行，高 14，`numberOfLines={1}`，再长的串也不换行、不把轨道挤短。
   - 柱高上限留出间隙：柱子高度按轨道高度的 85% 封顶（`Math.max(小值保底, (tokens / trendMax) * 85)`），最高柱顶永远离标签行有一段轨道空着，不再是 100% 顶满只剩 6px 间隙。
   - 长串缩字不截断：标签加 `adjustsFontSizeToFit`，`10000万` 这类串在窄屏下自动缩小字号塞进一行，不换行也不截掉数字。
   - 不改卡片总高（92px）与列宽：轨道仍按剩余空间 flex，比例关系不变，只是最高柱矮了一截、标签行钉死。

## Alternatives considered

- **只把按钮挪到页面顶部（汇总卡片上方）** — 最强的理由是改动最小：按钮仍在文档流里，不用处理悬浮定位、安全区、内容遮挡，测试也好断言。这是最初的方案，用户随后定版改成悬浮：顶部放法滚下去就看不见了，用户要的是「滚动时也一直在」，顶部满足不了。否掉，改悬浮。
- **只把按钮复制一份到顶部、底部保留** — 最强的理由是两处都能点到，不用用户翻页也不怕用户在底部找不到。但同一 destructive 操作在同一页出现两次，用户会疑惑两个按钮是不是不同行为；ux-declutter 的去重原则也是同一事实只留一处。否掉，底部删掉。
- **悬浮按钮放底部居中** — 最强的理由是拇指区正中、左右手都好点。但用量页底部内容是通话明细列表，居中悬浮会盖住每行记录的金额列；右下角只盖住行尾空白，挡住的东西最少，且与对话页跳至最新按钮同一角，用户已有肌肉记忆。否掉，放右下角。
- **只把柱高上限从 100% 降到 85%，不钉死标签行** — 最强的理由是改动最小，最高柱顶的间隙问题当场解决。但标签换行那条路还在：窄屏 + 大值 + 字体放大三者一叠加，标签行仍会长高、轨道仍被挤短，下次换个值又压回来。否掉，三处一起改才算结构修。
- **标签行改成绝对定位悬在卡片顶上** — 最强的理由是标签彻底脱离柱子布局，永远碰不到。但绝对定位要为每列算横坐标，7 列等宽下手写定位比 flex 脆弱，且标签与柱子的对应关系靠坐标硬对，窄屏下更容易错位。否掉，flex 布局内钉死高度更稳。
- **换图表库** — 最强的理由是现成库自带防重叠布局。但这页的图就是 7 根 div 级柱子，换库要引依赖、改取数、重测整页，只为修一个标签间隙，成本与收益不对等。否掉。

## Consequences

- 用量页右下角有一个悬浮「Reset usage」按钮，滚动时始终可见；点后弹同一确认框，确认后调一次 `usage/reset` 并刷新；全页只有一个重置按钮，底部那个已删；滚动到底时最后一行能滚到按钮上方、不被盖住。
- 柱状图：标签行单行固定高度；最高柱不超过轨道高度的 85%；`10000万` 量级的长串在窄屏下不换行、不截断。
- `usage.test.tsx` 6/6 绿（含 2 个新用例：悬浮按钮唯一且在滚动内容之外、近 7 天 compact 标签 `320万` 渲染）；`usage-detail.test.ts` 照旧；tsc 只剩 6 个与本次无关的基线错误（`usage-detail` 的 `totalOnlyCalls`，HEAD 已有）；Biome 全绿。
- 风险仍在：`adjustsFontSizeToFit` 在 Android 上对过长串的缩小幅度有限，极端窄屏 + 极大值仍可能截断；保底是 `numberOfLines={1}` 不换行，最差只丢末尾字符，不会再压到柱子。柱高封顶 85% 后最高柱视觉上矮一截，7 天对比的相对比例不变（同乘一个系数），只是绝对高度变小。
- 未验证：无真机/模拟器截图，悬浮按钮在手机上的实际位置（是否压住 home indicator、是否挡住明细行尾）与柱状图在真机窄屏下的实际间隙，待用户在下一包里核对。
