# Agent Note: 画廊管理——分类、排序、按天分组、长按多选、保存到本地、删除、重命名

Status: implemented

## Problem

网页版画廊（`apps/web/src/pages/Gallery.tsx`）原来只有一层平铺：机器人生成的图片和视频按生成时间倒序无限加载，点开预览后能单个下载。除此之外什么管理能力都没有：

- 图片和视频混在一起，没有分类。
- 只有最新在前一种顺序，不能按日期倒序、不能按大小排。
- 不能多选，不能批量保存到本地电脑或手机，不能批量删除。
- 文件名是生成时的 `generated-<id>.png/mp4`，改不了。

用户 2026-11-19 连续四次收紧需求并看过三版效果图后定版：分类、排序一键切换、按天分组、长按进多选、选中后保存到本地（zip）或删除、预览里重命名。范围只限网页版画廊，App 不动。

## Decision

画廊实现六件能力，全部只改画廊与 `artifacts` 这一条线：

### 1. 分类：全部 / 图片 / 视频

顶栏三个 tab，按 `mimeType` 在客户端过滤（`image/*` / `video/*`）。切换分类重置分页回到第一页。分类不建新查询键：查询只按 `sort` 分键，分类是客户端过滤 + 滚回顶部 + 重置自动翻页游标。

### 2. 排序：一个按钮点着切，日期排按天分组，大小排平铺

按钮循环四态：`日期 ↓`（最新在前，默认）→ `日期 ↑`（最早在前）→ `大小 ↓`（从大到小）→ `大小 ↑`（从小到大）→ 回到 `日期 ↓`。不做下拉菜单。

- 服务端 `artifacts.listSpace` 接受排序参数（日期/大小 × 倒序/顺序四种，`ArtifactListSortSchema`）。大小排序按 `(size, id)` 比较，日期排序按 `(createdAt, id)` 比较；游标编解码与 SQL 的比较方向都跟着排序走（倒序 `<`、顺序 `>`），`v1.` 前缀不变，老游标缺 `sort` 时按最新在前读。
- 按日期排时，客户端按本地日期分组，组头为 `今天 · 11月19日 · N 项` / `昨天 · 11月18日 · N 项` / `11月17日 · N 项`，跨年日期的组头带年份；图下显示当天时间（`14:32`）。
- 按大小排时不分组，直接按大小平铺，图下显示大小（`1.4 MB`）+ 机器人名。
- 切换排序重置分页回到第一页，并清空已选。

### 3. 长按进多选

不用「选择」按钮。长按（pointerdown 计时约 500ms，松开/滑动超 10px 取消，屏蔽随后的点击与右键菜单）任意一张图进选择模式，被按的那张直接勾上；再点其他图多选，再点取消勾选；选择模式下长按改为切换勾选。底栏：`已选 N 项` + `保存到本地` + `删除` + `取消`。取消退出选择模式并清空已选。长按与点按预览、滚动三者互不触发。

### 4. 保存到本地：选中的打一个 zip 一次下载

选中的文件逐个经 `artifacts.get` 取字节，在浏览器里用 core 暴露的 `zipFiles`（fflate `zipSync`，重名加 ` (2)` / ` (3)` 后缀）打成一个 zip（`rakazo-gallery-<日期>.zip`）触发一次浏览器下载。选中的总大小上限 500 MB，超了先报错、不开下载。保存后保留已选，方便接着删。预览里的单个下载（已存在）不变。

### 5. 删除：先确认，再调已有的 `artifacts.remove`

删除按钮先弹确认框：标题 `删除 N 项？`，正文 `删除后服务器上的文件无法恢复，请先保存到本地。`，按钮 `取消` / `删除`。确认后逐个调已有的 `artifacts.remove`（`deleteArtifactFamily`，整族删除），成功后按 `apps/web/src/pages/Artifacts.tsx` 已有的模式更新无限列表缓存并失效 `listSpace`；失败的单项报出哪一项没删掉，失败项留在选中态、对话框留着失败名单。

### 6. 重命名：新加 `artifacts.rename`

contract（`packages/contracts/src/rpc.ts` 的 `artifacts` 段）加 `rename`（入参 `{artifactId, name}`，出参 `{ok: true, name}`，返回服务端实际保存的名字，客户端不重复算扩展名规则），API 在 `apps/api/src/routes/content.ts` 的 `artifacts` 段加 handler，只改本空间内最新版本的名并校验归属与名字合法：非空、去首尾空格、保留原扩展名、长度上限 255；空名、纯扩展名、含 `/` 或 `\`、超长都报 `AttachmentValidationError`；归属校验失败或行已消失报 `IsolationError`。预览顶栏加「重命名」，点后标题变输入框 + `保存` / `取消`（支持 Enter/Escape）；保存后列表与下载用的都是新名字。图片和视频都能改。

### 文案与测试

- 新文案走 Lingui extract + zh-CN 翻译 + compile，中文文案以效果图为准。500MB 报错、删除失败、保存失败的英文文案是实现时现拟的，zh 翻译已补。
- 效果图里的视频时长角标（`0:05`）只是示意：artifact 行没有时长字段，不做时长角标，视频格仍只显示播放图标。
- 效果图顶栏的「128 项」总数没做（去噪）。

## Alternatives considered

- **排序用下拉菜单**：最强理由是四种排序一次看全、不用连点。否决：用户亲口要「就是切换下」，一个按钮点着切。
- **批量保存逐个触发多次下载**：最强理由是不用引 zip、实现最少。否决：手机浏览器会拦截多次连续下载；一个 zip 一次下载最可靠。
- **服务端出 zip 接口**：最强理由是手机只下一次且服务端算好。否决：要新加 API 与服务端打包开销，文件已在浏览器可取，客户端打包足够；fflate 已在依赖树里。
- **重命名建新版本**：最强理由是复用 artifact 的版本机制。否决：改名不是新内容，不应多一个版本；只改最新版本的名，生成文件 normally 只有一个版本。
- **删除不确认**：最强理由是少一步。否决：删除不可逆，用户已定先确认、并在确认里提醒先保存。

## Consequences

- 画廊顶栏有 全部/图片/视频，切换正确过滤；排序按钮按 日期↓ → 日期↑ → 大小↓ → 大小↑ 循环，分页在四种排序下都对；日期排按天分组、图下是时间，大小排平铺、图下是大小。
- 长按进多选，被按的已勾上；点按切换勾选；底栏保存/删除/取消都工作；不触发预览、不干扰滚动。
- 多选保存到本地下一个 zip，里面是选中的文件、文件名与改名后一致；超上限报错。
- 删除先确认，确认后服务器上的文件消失、列表同步；失败单项有报错。
- 预览里能重命名图片和视频，改名后列表与下载都用新名。
- 新文案中文显示正常（extract + zh-CN + compile 跑过），`pnpm verify-notes` 通过，相关单测与 `tsc` 按基线通过。
- 本次只做到本地提交，不推分支、不触发构建、不部署（另等用户点头）。

### 实现中发现的两个真缺陷（已修）

- **预览 effect 无限渲染循环**：`GalleryPreview` 里 `artifactTarget()` 每次调用返回新对象，视频加载 effect 的依赖含 `target`，于是每渲染必重跑；图片分支又无条件 `setVideo({ status: "idle" })` 建新对象，点开预览即死循环。修法：`target` 用 `useMemo` 按 `botId` / `groupId` 稳定下来，idle 重置用函数式更新、已是 idle 就返回原对象。教训：effect 依赖里不要放每次新建的对象；无条件 `setState(新对象)` 放在 effect 里就是循环。
- **裸 `t` 导致预览一点就白屏**：视频加载 effect 的依赖数组里写了裸 `t`（想跟 locale 走）。Lingui macro 只转换 `t`...`` 模板用法，裸 `t` 在真实构建里没有绑定，点开预览即 `ReferenceError: t is not defined`，整页卸载。修法：把 `t` 移出依赖数组（effect 体里的 `t`...`` 本身是 macro 用法，运行时已是 `i18n._`，locale 变化不需要重跑 effect）。教训：vitest 里 `@lingui/core/macro` 是 mock（`t` 是真函数），这类错单测永远抓不到；只有真实浏览器能抓到，见 Testing 里的 e2e。

### 与提案不一致的地方

- `artifacts.rename` 出参是 `{ok: true, name}`，不是 `{ok: true}`。
- 分类切换不建新查询键（见 Decision §1）。
- 重命名多了一条 `/`、`\` 校验，提案未提。
- 排序/分类切换时清空已选；保存后保留已选；选择模式下长按改为切换勾选。
- 跨年日期的组头带年份，提案未提。
- 改名后若新名不再以 `generated-` 开头，该项会从画廊的生成媒体过滤中消失——这是过滤规则本身的行为，不是缺陷；测试用例改名时用仍以 `generated-` 开头的名字。
