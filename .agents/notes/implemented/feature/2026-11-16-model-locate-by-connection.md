# Agent Note: 模型定位按模型 id 加连接名匹配

Status: implemented

## Problem

两个连接上有同名模型时，按模型 id 定位会落到错误行；短 id（deepseek-flash）与 catalog id（deepseek-v4.1-flash）未桥接，三方连接定位不到；网页气泡里的「当前模型:」行是纯文本，点不了。

## Decision

定位按模型 id 加连接显示名匹配；短 id 与 catalog id 在任何提供商上都桥接；译文栏不带提供商时，优先落到机器人当前模型行；网页下拉自动打开并滚到被定位行、标「Located here」，备选行也能标，模型不在列表里时标留区段；网页气泡末尾的「当前模型:」行剥出来变成可点栏。

## Alternatives considered

- **只按模型 id 匹配** — 实现最简单；但同名模型分不清，1.0.29 验收当场落错行。
- **只按行 key（provider-id::modelId）匹配** — 精确；但三个连接共享一个 provider id，key 区分不开连接。
- **定位失败时不显示任何标记** — 简单；但用户不知道面板有没有响应，标留区段至少说明「来对地方了，模型已不在」。

## Consequences

- **收益**：定位精确到连接；无提供商的定位也有合理落点；网页气泡终于能点。
- **代价与已知上限**：匹配逻辑多一层，备选行与主行要分别处理；模型后端不稳时，定位再准也换不出可用模型。

## Verification

1.0.30 已部署；网页相关测试 71+79+60 全过；服务端镜像 sha-54bba2f5 已上线。
