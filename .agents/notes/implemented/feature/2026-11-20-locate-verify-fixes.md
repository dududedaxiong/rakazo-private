# Agent Note: 定位实测五项修复：主池行进列表、选择器不自动开、主模型小窗补提供方、编辑源图取 storageKey、有色边框与焦点落行

Status: implemented

## Problem

定位流程上线后，网页实测发现五项问题（2026-11-20 11:46–11:50，New Bot 对话），用户 12:05 亲口说“现在修”，12:08 又补了焦点要求。只改代码、测试、推送到新分支，不部署、不触发构建。

- ① 全部家族（生图、视频、图片编辑、视频编辑、翻译）的主池都显示“主池（1）”，但标题下直接就是“添加主池模型”下拉，没有任何模型行（无障碍树里也没有），点不到、换不了；备用池的横幅卡片正常。
- ② 点定位小窗的名字跳转后，切换记录与小窗关了，但当前模型选择器（带搜索输入的列表框）自动打开，盖住设置面板一部分；且选择器列表里被定位项截断成“cogv…”。
- ③ 主聊天模型的定位小窗按钮只有模型名，没有“（提供方）”；影图那条有。
- ④ 对一张已生成的图点细节修改，补充提示词后约 30 秒对话出现失败行“图片编辑失败：要编辑的图片不可用”。编辑列表读取已修好（这次没再报“还没有配置编辑模型”），不要回退那处。
- ⑤ 被定位行边框是加粗黑色而非彩色；设计是 `border-2 border-primary` + 底色。
- ⑥（用户 12:08 补）定位后焦点要落在被定位到的模型行上，让他一眼就知道模型在哪：跳转到模型列表后，把键盘焦点（及视觉焦点）落到被定位的那一行，而不是落在选择器搜索框里；选择器不要自动打开、不要抢焦点。边框高亮保留，焦点聚焦是额外的一层。

不用改的（实测已确认符合设计，别动）：替换打开的是与“添加模型”同一原生 `<select>`（本来就没有搜索框）；详情展开没有“图片输入”一行是符合设计的（目录知道才显示）。手机端窄屏（390px）桌面测不了：只复核代码，不新写代码；实测等用户手机验收。

## Decision

### 1. 主池行：主模型并进主池列表当第 1 行卡片，首位选择器行去掉

根因不在计数与行列表的数据源不同（`splitBotModelPools` / `mapBot` 的视图-存储拆分猜测已证伪）：`MediaRoleSection` / `TranslationGroup` 里主模型单独占上面一行选择器，主池列表只收主池“首位之后”的模型（`bot-panel.tsx` 里 `toFallbackRows(videoMainModels.slice(1), …)`）；计数是 `(value ? 1 : 0) + mainFallbacks.length`，所以单主模型时标题显示（1）、列表里 0 行。

- 组件内部合并，不改调用方池子数据：`MediaRoleSection` / `TranslationGroup` 保留 `value`（主模型 key）与 `mainFallbacks`（首位之后）的 props，内部拼出 `mainRows = value ? [{ key: value, label: 主模型 label }, ...mainFallbacks] : mainFallbacks`，主池列表改收 `mainRows`。主模型 label 从连接选项里按 key 查，查不到退到 key 本身，不编造。
- 首位选择器行去掉（否则同一模型出现两次），家族名（例如“视频生成模型”）留作普通标签行；主模型改选走卡片的替换（与“添加模型”同一原生选模型器），不再有可搜索弹层。
- 主池列表默认展开：现在非空列表默认折叠（主模型在选择器行里可见时合理）；主模型进列表后，主池 `defaultOpen` 改为真，否则主行仍藏在“主池（1）”后面。备用池仍默认折叠。
- 第 1 行的上移按钮禁用（已是池首，无处可移）；下移照常（下移即让出主模型位置）。第 1 行的删除照常：删掉主模型后下一行顶上成为主模型。
- 主行的测试结果走列表行内结果（每家族只有一个测试状态，主行与列表行共用，旧的选择器行下那份独立结果随行去掉）。主行不显示“设为主模型”（它已经是主模型，点下去是空操作）。
- 选择器行去掉后，`changeMediaModel` / `changeTranslationModel`（只剩 picker 的 `onChange` 在调）随之一并删掉，四个 `onXModelChange` props 与翻译的 `onModelChange` prop 同删，不留死代码。
- 行为变化（已接受）：旧选择器选“未选择”会清空主池与备用池两池；新做法是逐行删，删主行只删这一行、不动备用池。清空整个家族改成逐行删。

### 2. 定位不自动打开选择器；选择器选项名不截断

- 三处 `autoOpen`（聊天、翻译、影图主模型行）全删；`ChatModelPicker` 的 `autoOpen` prop、`autoOpenedKey` 状态与自动打开的 effect 一并删掉。定位到的行仍打 tag；用户自己打开选择器后，打开时的滚到被定位行保留（只在 `open` 时跑）。
- 选择器选项名去 `truncate` 改 `break-words` 换行完整显示；触发按钮的名字同样不截断。粗指针设备 `initialFocus={false}` 不动。

### 3. 主模型定位小窗补提供方

- `ModelSwitchMarkButton` 只传 `{ kind, botId, model }`，没传 provider；时间线路径带 `attempt.provider`（连接显示名），所以影图那条有。聊天 mark 只有 modelId（+预设名，不是提供方），提供方只能从机器人当前模型取。
- 链路：`peerBot` 返回类型加 `modelProvider` / `modelId` / `modelProviderLabel`，在 `resolveTranscriptBot` 里用 `credentialForModel(credentials, provider, modelId)?.label` 算；`message-view.tsx` 两处 MarkButton 调用点只在 mark 模型与机器人当前模型同 id（用 `sameModelId` 比，桥接短 id 与目录 id）时才传 provider，否则留空——不猜，同名模型在多连接上猜错比留空更坏。

### 4. 细节修改：编辑源图按 `storageKey` 取字节，不按行 id

根因已定位：`loadMediaReferences`（`packages/adapters/src/media-video-poll.ts`）用行 id 取字节：`deps.artifacts.get(artifact.id, …)`，应传 `artifact.storageKey`。除它之外全仓库所有 `artifacts.get` 调用点都传 `storageKey`。artifact 行的 id 是 cuid，`storageKey` 是 `artifacts.put` 返回的新 UUID（对象存储时为 `object:<uuid>`，本地盘时为裸 UUID），两者永远不相等；本地盘 `forId(cuid)` 找不到文件 → ENOENT → 被 catch 成 undefined → 编辑模式判“图片不可用”，根本没到 cogview 守卫。由异步化重构（随 2026-11-19 11:37 上线）引入的回归。

修法：`loadMediaReferences` 里 select 增加 `storageKey`，`get(artifact.storageKey)`。同函数还影响视频编辑（参考帧同路）与视频轮询重提交的参考帧加载。修好后 cogview 编辑应走到守卫、诚实报“不支持图生图”（见失败原因显示笔记的摘要映射）。

### 5. 被定位行边框改 link 蓝

`border-primary` 的 class 确实在生效（2px 描边可见），颜色是墨色是因为应用是单色设计、primary token 即墨色——不是 class 失效，是颜色按设计就是墨色。用户要的是有色边框。

- 被定位卡片的边框 `border-primary` 改 `border-link`；`LocatedTag`（描边 + 文字）与聊天节卡片的 `ring-primary` 同步改 link，定位高亮保持一种颜色。
- 颜色选 link 蓝：它是已有的语义 token（浅色 `#0b6dd3`、深色 `#4d9bff`），模型名文字已在用 `text-link`，同界面已在用，不新造 token、不硬编码色值（仓库规则：颜色只走 `ui-tokens` 的语义 token）。
- 上一批笔记 §4 选墨色的理由（“link 蓝与已有的定位标记不同色，所以不用”）被本次用户要求翻转：用户明确要彩色，标记与边框一起改成 link 蓝，仍同色。老笔记 §4 加互链说明。

### 6. 焦点：定位后落在被定位的行上

- 池子行由列表自己聚焦：列表打开且 `locatedKey` 命中本列表某行时，焦点落到该卡片的横幅按钮（行内第一个控件，带 `focus-visible` 描边；点它才展开详情，聚焦本身不展开）。主模型行进列表后同样是卡片行，同理。
- 聊天模型行仍是选择器行（不在池子列表里），由面板的定位 effect 聚焦：滚动后聚焦该行里的选择器触发控件（长列表是按钮，短列表是原生下拉）。
- 模型已不在列表时（`locatedKey` 为 null，section 本身是定位目标），聚焦 section 容器本身（加 `tabIndex={-1}`）；池子行由列表聚焦时面板不再重复聚焦。
- 选择器不自动打开、不抢焦点（§2）；焦点只在用户点了时间线名字之后落下，不在页面加载时抢。

### 7. 手机端窄屏只复核代码

粗指针设备 `initialFocus={false}`、下拉框换行（§2 的 `break-words`）复核代码即可，不新写代码；390px 实测等用户手机验收。

## Alternatives considered

- ① 调用方把主模型塞进 `mainFallbacks`（`toFallbackRows` 不再 `slice(1)`）：最强的理由是调用方一次改完、组件不用合并。但池子数据是真相来源，显示合并放组件内，调用方与测试骨架不动，改动面更小；不用。
- ① 只改计数让标题诚实（主池显示 (0)）：数字对了，但用户要的是行能点能换，不是数字诚实；不用。
- ① 保留选择器行、主池列表也显示主模型：同一模型出现两次，改选入口分裂（选哪边都改同一个池子，但看起来像两个模型）；不用。
- ② 保留 `autoOpen`、只修选项截断：自动打开的弹层盖住设置面板是问题本身，截断只是附带；不用。
- ③ 小窗里不显示提供方、只显示模型名：改动为零，但用户明确要求与影图一致；不用。
- ③ 从连接列表按 modelId 反查提供方：同名模型在多连接上各有一行，反查可能指错连接，猜错比留空更坏；不用。
- ④ 在 artifact store 层让 `get` 同时接受行 id：store 的 key 契约就是 `storageKey`，全仓库其他调用点都传 `storageKey`，改一处调用点比改 store 契约小；不用。
- ⑤ 新加一个语义 token（例如定位蓝）：为一次高亮加新 token 没必要，link 蓝已是现有 token 且同界面已在用；不用。
- ⑤ 硬编码 hex：仓库规则禁止（颜色只走语义 token）；不用。
- ⑥ 聚焦整行 div（`tabIndex`）：整行得焦点时视觉上最整，但键盘用户落到行内第一个控件（横幅按钮 / 选择器触发）才是自然落点，Tab 顺序不断；不用。
- ⑥ 只给视觉高亮、不给键盘焦点：用户明确要求键盘焦点；不用。

## Consequences

- 主模型从此是主池列表的第 1 行卡片：替换、测试、上移、下移、删除、展开详情、定位边框、焦点，全部走卡片同一套；首位选择器行与它的可搜索弹层消失，主模型改选走替换；主池默认展开。
- 定位跳转不再自动打开任何选择器；选择器选项名与触发按钮名完整换行显示。
- 主聊天模型定位小窗显示“模型名（提供方）”，与影图一致；机器人换了当前模型后，旧消息的 mark 不再硬指新模型的提供方（同 id 才传）。
- 图片 / 视频编辑的源图与参考帧重新能取到字节；cogview 这类纯文生图模型点细节修改时走到守卫、报“不支持图生图”，不再报“图片不可用”。
- 定位高亮统一为 link 蓝（卡片边框、标记、聊天卡片 ring）。
- 定位后键盘焦点落在被定位行（卡片横幅按钮 / 聊天选择器触发控件 / 无匹配时 section 本身）。
- 代价：旧选择器“未选择”一键清两池的做法随行消失，清空家族改成逐行删；主池默认展开后设置页变长一截（用户可再折叠）。
- 未验证：没有 live 浏览器视觉核对（桌面浏览器改不了视口宽、且本批不部署）；手机端窄屏三处等用户手机验收；Postgres 轮询测试本地跳过（无数据库），走 CI。
