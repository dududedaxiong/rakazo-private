# Agent Note: 机器人长期记忆：触发条件、版本快照与审计

Status: proposed

## Problem

Rakazo 的机器人没有长期记忆的设计：对话历史存在，但「记得什么、什么时候想起、记错了怎么办」没有规矩。过去吃过的亏：凭截图推断连接名结果记错、否掉的老路被反复重提、翻译没持久化之前刷新就丢。记忆一旦写错，没有回滚、没有审计，用户只能口头纠正，纠正成本全落在用户身上。

## Proposal

借鉴 Nocturne Memory 的三条机制，给机器人记忆立规矩（只定设计，不定实现）：

- **触发条件（disclosure）**：每条记忆绑一句话触发条件，如「当用户提到项目 X 时」；模型按当前情境精准调取，不靠全文检索盲抽。
- **版本快照与回滚**：每次改写记忆自动生成快照；记错了可一键回滚到任意历史版本，而不是靠新对话覆盖。
- **审计**：记忆的每次写入、修改、回滚都留痕，用户可在界面里查看 diff、接受或拒绝。

开放问题：触发条件的写法与校验方式、快照保留多久、审计入口放在网页还是 App。

## Alternatives considered

- **只用向量 RAG** — 实现最简单；但检索到的是碎片，丢失层级与因果；且 RAG 只读，AI 能查不能修正自己的记忆，记错了只能靠新数据覆盖。
- **直接部署 Nocturne Memory 服务** — 现成可用；但它是给 MCP 客户端（Claude Code 等）做的独立 Python 服务，Rakazo 接入要另起一套服务加维护；且作者已转去做 Horon，Nocturne 只做维护更新。
- **什么都不做，维持现状** — 零成本；但记忆问题会随着对话量增长继续出现，纠正成本全落在用户口头上。

## Acceptance criteria

- 机器人能在提到相关话题时调取对应记忆，不靠用户重复提醒。
- 记忆写错后，用户或 assistant 能回滚到改写前的版本。
- 记忆的写入与修改有记录可查。

## Risks

- 记忆越攒越多会变噪声，需要定期诊断（过时、重复、孤儿记忆），否则该想起的想不起来。
- 触发条件写不好会误召回或漏召回，需要先在小范围验证。
- 回滚与审计是新界面工作量，网页与 App 都要补入口。
