# Agent Note: 语音对话的轮次检测：本机 VAD + Smart-Turn

Status: proposed

## Problem

网页 / App 的语音实时对话一直暂缓，其中一个难点是轮次检测：什么时候算用户说完了、该模型接话。靠服务端等静音超时会卡（首字 60s、断流 30s 是聊天用的阈值，不适合语音对话）；靠云端 ASR 流式识别又多一跳、还得多花钱。

用户要的是豆包式通话：**关键是随时打断**——AI 朗读时用户一开口就停、立刻切回听；用户说完后生成对话并朗读出来。打断不是附加功能，是这个通话成立的前提。

## Proposal

借鉴 dsh-Go 的做法，轮次检测放本机做（只定设计，不定实现）：

- **VAD**：Silero VAD（ONNX，16kHz，512 采样帧）判断有没有人在说话，单线程跑在手机上。
- **Smart-Turn**：Smart-Turn v3.2（ONNX，输入为 Whisper mel 80x800）判断这句话说完了没有。
- 识别分两路，**本机流式识别首选**：sherpa-onnx Zipformer 中英双语模型（Apache-2.0，约 198MB，首次下载、SHA256 校验），边说边出 partial 结果，静音 1 秒断句，最长 110 秒；**整段识别作回退**：DeepSeek ASR / OpenAI 兼容 `/audio/transcriptions` / 引擎自带语音模型三选一，按配置回退。模型与运行库均为 Apache-2.0，可直接用，不像 AGPL 代码只能借鉴设计。
- 单麦克风仲裁：同一时间只有一个语音功能占麦，别的先停。**通话里这条要改**：朗读时麦克风必须保持开启（全双工），否则打断做不了；打断时 VAD 检测到用户说话就立即停 TTS、切回听。

- **打断（核心）**：状态机 听 → 识别 → 生成 → 读 → 听，读和生成两个态都能被打断回听态。回声消除是前提：朗读时麦克风会收到自己的声音，靠平台回声消除（网页 getUserMedia echoCancellation、Android 用 VOICE_COMMUNICATION 音源），否则 VAD 会被自己的朗读音触发。

- **流式朗读**：回复分句合成、首句就绪即读，边生成边读，不用等整段回完——这是豆包式低延迟体感的来源。

朗读不缺：本机已有 TTS 能读，首版可以「整段回、整段读」先跑起来；回复边生成边读（分句合成、顺序播放、打断处理）是后面的优化，不是前置条件。

实现路径按省事程度排：**服务端 VAD**（onnxruntime-node 跑在服务端，一处实现、网页和 App 都能用；要补一条音频流通道，现在语音输入是整段文件上传）→ **网页 WASM**（onnxruntime-web + getUserMedia，纯前端、原型最快）→ **App 本机**（onnxruntime-react-native 有官方包，Expo 走 prebuild + config plugin 能接；难点在 Expo 里拿实时 PCM 音频流，现在按住说话是录完整段再发）。模型本身不用训，是现成的 ONNX 文件；难在音频管道和阈值调参，不在模型。

现状评估（2026-11-16，用户问能不能做到豆包那样）：**能做，但不是现成拼起来**。已有的三件：流式聊天回复、本机朗读、整段语音识别。缺的三件：① 轮次检测与音频流通道；② 打断（全双工 + 回声消除 + 快速停 TTS）；③ 分句流式朗读。另有两个条件限制：聊天模型后端目前不稳（主模型 503、GB 密钥 401），通话会继承这个不稳定；手机扬声器外放时回声消除靠设备，戴耳机基本没问题。先做「准实时」版（整段轮次 + 打断），豆包级流畅要再加流式识别和流式朗读。

只借鉴设计，不搬代码（AGPL-3.0）。

## Alternatives considered

- **服务端静音超时切轮次** — 实现最简单；但延迟大、误切多，语音对话体验差。
- **云端流式 ASR 边说边识别** — 实时性好；但多一跳、按量计费，且识别服务本身要稳定。
- **系统语音识别（Android SpeechRecognizer）** — 零成本、带 partial 结果；但依赖厂商服务、行为不可控，只适合语音输入，不适合通话。

## Acceptance criteria

- 用户说完后，模型在可感知的短时间内接话，不靠固定超时硬等。
- 安静时不误触发，嘈杂时不把半句话切成两段。
- 麦克风同一时间只被一个功能占用。

## Risks

- 本机 ONNX 模型要进 App 包，体积与耗电要评估。
- Smart-Turn 对中文的切分效果需实测，不能默认和英文一样准。
- 流式识别模型约 198MB，首次下载与手机 CPU 占用要评估；云端整段识别作回退时仍有「录完再识别」的延迟。
- 回声消除不到位时，AI 会听到自己的朗读声、误以为用户在说话，导致朗读被自己的声音反复打断——这是打断功能最常见的失败形态，须真机实测。
