# Agent Note: 发往上游中转前本地脱敏，回复再还原

Status: proposed

## Problem

Rakazo 把用户消息原文发给第三方中转（GB、免费中转等）。用户消息里可能带密钥、连接串、手机号、身份证等敏感内容；过去用户也曾在聊天里直接贴过密钥。第三方中转不可信，一旦发出就收不回；目前没有任何脱敏环节。

## Proposal

借鉴 Maskit 的做法，在服务端加一层可选的脱敏（只定设计，不定实现）：

- **发送前**：按规则（密钥、连接串、手机号、身份证、邮箱等）与用户自定义词表，把敏感内容换成确定性占位符（如 `{{PHONE_xxxx}}`），同一会话同一敏感词映射不变，保证多轮推理一致。
- **回复时**：流式还原占位符为原文，用户看到的仍是完整回答。
- **开关**：按连接或按机器人开启，默认关；脱敏日志只记占位符与哈希，不落盘原文。

只借鉴设计、自己实现，不直接搬 Maskit 的代码（AGPL-3.0）。

## Alternatives considered

- **cue 上起 Maskit Docker 网关，接在中转前面** — 现成可用；但多一跳、多一个要维护的服务；且只覆盖经网关的流量，Rakazo 直连中转的调用走不到它。
- **什么都不做** — 零成本；但敏感内容继续原文发给第三方中转。
- **提醒用户自己别发敏感内容** — 零成本；但靠自觉，用户已经贴过密钥，拦不住。

## Acceptance criteria

- 开启后，中转侧收到的请求正文里没有原文敏感内容。
- 用户看到的回复与未脱敏时一致（占位符已还原）。
- 脱敏日志里查不到原文。

## Risks

- 规则误杀：正常内容被当成敏感词打码，影响模型理解；需要可调的规则与白名单。
- 占位符可能被模型复述或改写，还原要处理跨 chunk 拼接与变形。
- 图片与附件里的敏感内容（截图、PDF）不在本提案内，另议。
