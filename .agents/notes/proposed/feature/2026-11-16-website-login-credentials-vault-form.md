# Agent Note: 网站登录凭据走加密表单，模型看不到明文

Status: proposed

## Problem

以后要让 AI 替用户登录网站时，密码怎么给 AI 是个问题。现在的做法是把密码发在聊天里——密码会经过中转站（第三方模型提供商），中转站全看得到。用户以后会接更多中转站，这个口子必须堵上。

## Proposal

照 Muse 的安全表单做法：

- 用户在 App / 网页的表单里填网站账号密码，提交后进服务端加密存储（复用现有的 Secret 表与 ENCRYPTION_KEY），不进聊天记录、不进模型上下文。
- 浏览器自动化填表时，由服务端模块直接从加密存储取用并填入，模型只收到「已填入 / 登录成功 / 失败」的结果，看不到账号密码明文。
- 凭据绑定网站来源（origin）：只在匹配的域名上自动填，防钓鱼页骗取。

## Alternatives considered

- **密码发在聊天里让模型填** — 最省事；但密码经过中转站，任何一个中转都能看到。
- **密码写进配置文件明文存** — 实现简单；但服务器一旦泄露就全漏，且无法按网站分权限。
- **不支持 AI 登录网站** — 零风险；但用户明确以后要用这个功能。

## Acceptance criteria

- 中转站收到的请求里不出现账号密码明文。
- 模型上下文里不出现账号密码明文。
- 凭据只在目标网站的域名上自动填，别的域名不填。

## Risks

- 浏览器进程里填表那一刻仍有明文，沙箱本身必须可信；沙箱被攻破则凭据仍可能泄露。
- 自动填表可能被钓鱼页利用，origin 绑定是必须的，不能只靠域名后缀匹配。
- 用户忘记凭据存在哪、或服务端加密密钥丢失，凭据无法恢复（与现有 Secret 表同一约束）。
