# Agent Note: 管理员登录 2FA 与受超级密钥保护的设置页（响应式管理页）

Status: proposed

## Problem

管理员登录今天只有一道认证：密码、邮箱验证码、SSO 或 Passkey，任一通过即获得完整管理权限（用户管理、邀请码、IP 封禁、注册开关）。管理员身份只由“邮箱已验证 + 邮箱在管理员名单里”判定，登录本身没有第二因素；一旦管理员的登录凭据泄露，整个管理面就被接管。

另外两个缺口：

- 邮箱发送配置今天只存在服务端环境变量里，管理后台看不到、测不了；2FA 本身也没有配置入口。
- 管理页是固定桌面布局（左侧固定宽度边栏 + 居中内容列），在手机上操作困难，而管理员实际经常在手机上操作。

## Proposal

分三件做，都是管理面收紧，不动普通用户的登录流程。

### 1. 管理员登录加 TOTP，只给管理员

- 管理员完成现有第一因素（密码 / 邮箱验证码 / SSO / Passkey）后，再过一道 TOTP（RFC 6238，6 位、30 秒窗口，允许 ±1 步时钟漂移）。
- 只针对管理员账号：非管理员的登录流程完全不变，不提示、不注册、不强制。
- 注册（enrollment）在新的 2FA 设置页里做：扫码（otpauth URI）后输入一码验证通过才激活；TOTP 密钥进服务端加密存储，复用现有的 Secret 表与加密密钥（与[网站登录凭据表单](./2026-11-16-website-login-credentials-vault-form.md)同一做法，密钥明文不进聊天、不进模型上下文）。
- 恢复：启用时发一次性恢复码（单次有效、只存哈希）；恢复码与验证器都丢了时，走超级密钥门禁重新注册。
- 校验必须在服务端做：TOTP 尝试限速、失败记审计日志；前端只负责收码。
- 实施定版：引入 otpauth（9.6.0），不手写加密原语；otpauth URI 的 issuer 用产品名；恢复码 10 个、8 字符无歧义字母表、显示为 XXXX-XXXX、只存 scrypt 哈希、单次有效。

### 2. 两个新设置页，进页先过超级密钥验证

管理后台新增两个页面：邮箱配置设置、2FA 设置。进入任一页面之前，先过超级密钥验证：

- 输入超级密钥 → 服务端用等时比较校验 → 通过后发一个短期会话授权（例如 15 分钟，仅用于这两个设置页）→ 授权过期要重新验证。
- 门禁必须在服务端强制执行：两个页面的读取与写入接口都要校验授权，只在前端隐藏页面等于没有门。
- 超级密钥来自服务端环境变量 ADMIN_SUPER_KEY（只记变量名，不记值），值只打在服务器配置里；授权有效期 15 分钟。
- 超级密钥可在 2FA 设置页里改（2026-11-17 用户定版）：该页本身在门禁后，改密钥前先过当前密钥验证；新值进 Secret 表加密存、立即生效、记审计；数据库有值时优先用数据库的，环境变量只作兜底；环境变量未设且数据库无值时门禁拒绝，不设代码默认值。
- 超级密钥连续输错要限速并记审计日志；授权本身也要记审计日志（谁、何时、进了哪个设置页）。

邮箱配置设置页可编辑（2026-11-17 用户定版）：服务商（Resend / 自建邮箱·免密钥 / SMTP / 无）、发件地址都能在页面上改；选 Resend 时填 API 密钥，选自建/SMTP 时填服务器地址、端口、账号、密码——自建邮箱走 SMTP 不用 key，用账号密码登录。密钥加密存，页面上只显示是否已配、不回显明文；保存后立即生效（下次发送即用新配置，不重启），改动记审计日志。服务端环境变量留作兜底：页面上没配的项用环境变量的值；不做自动迁移，页面显示环境变量的生效值，保存时才把显示的值写进数据库。测试发送保留；账号无密码时保存不拦截，发送时由服务端报错、测试发送可见。

实施偏离（2026-11-17）：邮箱密钥不进 Secret 表，改用 DeploymentSettings 的加密列（emailApiKeyCipher / emailSmtpPasswordCipher），用 SecretStore 以固定 recordId 密封——Secret 行是用户所有、删账号会级联丢掉部署级配置，部署级配置必须用加密列（先例：computerProviderCipher）；加密原语与密钥与 TOTP 密钥相同。另：解析型 provider 只在 API 进程内生效，worker 的机器人邮件仍走环境变量（worker 不能引用 apps/api 的代码，移入共享包是后续工作）。

### 3. 管理页响应式，自动适配手机与电脑

- 管理页布局按宽度自适应：窄屏时固定侧栏改成顶部栏或可收起导航，内容列全宽；宽屏保持现有侧栏布局。
- 两个新设置页从一开始就按响应式做；现有管理页只改布局，不改行为。
- UI 完成前按 UX 简化复核走一遍（仓库已有此要求）。

已定（2026-11-17 实施时）：恢复码 10 个、8 字符无歧义字母表；超级密钥授权 15 分钟；数据库优先、环境变量兜底；不做自动迁移（见上）。

## Alternatives considered

- **用 Passkey（WebAuthn）做管理员第二因素** — 最强理由：抗钓鱼、体验好，而且代码里已有 Passkey 登录与设置的现成件；为什么不用：用户已定 TOTP，手机验证器 App 即开即用，不依赖浏览器与平台的 Passkey 支持；且 Passkey 在本产品里是替代第一因素的登录方式，TOTP 是叠加在现有登录之上的第二因素，定位不同。
- **2FA 覆盖全部用户，不只管理员** — 最强理由：全员 2FA 更安全、规则统一；为什么不用：用户已定只给管理员；普通用户多一道门槛会挡人，管理员是唯一的高权限面，先收紧这里。
- **超级密钥放代码默认值或数据库** — 最强理由：实现最简单，部署不用多配环境变量；原先为什么不用：仓库是公开的，代码里的默认值等于公开；放数据库则密钥与被保护的配置同库，管理员权限被盗即连带泄露。2026-11-17 用户定版：默认值只来自服务端环境变量（代码里不设默认值），但密钥可在 2FA 设置页里改，改后的值进 Secret 表加密存、数据库优先、环境变量兜底；可改是用户的明确要求，泄露止血靠改密钥与审计。
- **超级密钥门禁只在前端隐藏页面，后端不校验** — 最强理由：改动最小，前端路由守卫几行代码；为什么不用：前端隐藏等于没有门，直接调接口就能绕过；敏感操作必须服务端校验。
- **邮箱配置也进数据库、后台可改** — 最强理由：管理员不用碰服务器就能改发件配置；原先为什么没做（现阶段）：发件密钥是基础设施凭据，现有惯例是环境变量；进数据库意味着密钥要过管理接口、还要处理热重载与审计。2026-11-17 用户定版改为可编辑：密钥进 Secret 表加密存、页面不回显、保存立即生效并记审计、环境变量留作兜底；超级密钥门禁本身就是这页的保护层。
- **管理页保持桌面布局，手机用缩放凑合** — 最强理由：零改动；为什么不用：用户在手机上实际操作管理页，固定侧栏在小屏上挤占内容，新页面从一开始就按响应式做。

## Acceptance criteria

- 管理员登录：启用 TOTP 后，只过第一因素进不去管理面；输对 TOTP 码才能进；输错限速并记审计日志。
- 非管理员登录流程无任何变化（不提示 TOTP、不强制注册）。
- 未通过超级密钥验证时，两个新设置页在界面上打不开、对应接口也拒绝；输错超级密钥限速并记审计日志。
- 超级密钥的值不出现在仓库、笔记、日志里的任何地方。
- 超级密钥可在 2FA 设置页修改，修改前须通过当前密钥验证，修改后立即生效并记审计；数据库无值且环境变量未设时门禁拒绝。
- 邮箱配置页能显示当前生效的发件配置状态，服务商、密钥、发件地址可改，保存后立即生效并记审计，测试发送能走通；密钥明文不出现在页面、接口回包与日志里。
- 管理页在手机宽度下可用（导航不挤占内容），在桌面宽度下保持现有布局。
- `pnpm verify-notes` 通过。

## Risks

- TOTP 密钥丢了无法恢复：复用 Secret 表与加密密钥，服务端加密密钥一旦丢失，TOTP 密钥与现有凭据一样无法恢复；恢复码与超级密钥重注册是唯二的后路，运营方必须备份好超级密钥。
- 超级密钥本身成了单点：如果超级密钥泄露，两个最敏感的设置页就被打开；缓解靠限速、审计日志，以及超级密钥与 TOTP 密钥分开存放、分开轮换。
- 超级密钥可改的副作用：当前密钥一旦泄露，攻击者可顺手改掉并锁死管理员；恢复靠服务端清掉数据库值（回落到环境变量），审计日志里能看到是谁改的。
- TOTP 时钟漂移：服务端与手机时钟差过大时验证码对不上；±1 步窗口缓解，仍对不上时走恢复码。
- TOTP 验证码在 30 秒窗口内可重放：同一码在窗口内可再用一次；攻击者还需同时持有第一因素会话，影响有限；后续可在 Secret 行上记上次计数器再收紧。
- 响应式改动回归风险：改管理页布局时可能碰到现有页面；只改布局不改行为，改完逐页在手机与桌面宽度下复核。
- 发件密钥进数据库：管理员权限被盗即连带泄露发件密钥；缓解靠超级密钥门禁、Secret 表加密、审计日志，以及密钥可轮换（页面上直接换）。
- 与[中转站分层防护](../architecture/2026-11-16-untrusted-relay-layered-defense.md)同一前提：本提案不解决“管理员自己把官方密钥交给中转站”的问题，只能靠提示与默认值引导。
